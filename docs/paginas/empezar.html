Empezar

Tres formas de usarlo

Conectar una API por enlace, embeber el visor en tu propio host, o levantarlo en local para desarrollar. En ese orden de esfuerzo.

1 · Conectar por enlace (?conn=)

La forma normal. ?conn= lleva un JSON en base64url con la base de la API y la marca. El visor lo decodifica y pide el documento antes del primer pintado — quien abre el enlace no configura nada.

  1. Arma el JSON de conexión

    Solo apiBase es obligatorio. El resto tiene valores por defecto.

    {
  "apiBase": "https://tu-host/api",
  "title": "ISS PatyIA",
  "icon": "mdi:robot-happy-outline",
  "fixedServer": true
}

  2. Codifícalo en base64url

    Base64 estándar con +/ → -_ y sin = de relleno. El visor tolera el padding si lo dejas. 

    // En el navegador
const b64url = (obj) => btoa(
  String.fromCharCode(...new TextEncoder().encode(JSON.stringify(obj)))
).replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

  3. Pégalo en la URL del visor

    https://tu-host/docs/?conn=eyJhcGlCYXNlIjoi…

    Y ya está: ese enlace abre tu API documentada y probable.

Campos de conn

Campo Por defecto Qué hace
apiBase — Base /api del host. Obligatorio.
auto true Conectar al cargar, sin pedir confirmación.
embed false Modo iframe: quita el chrome que el host ya pone.
fixedServer false Oculta el selector de servidor. Útil en producción.
title · icon Del documento Marca en la barra superior.
paths Rutas del ISS Override si tu host expone la config en otra ruta.

Los paths por defecto son los que el ISS ya expone: /system/swagger/config.json, /system/swagger/meta.json, /system/swagger/paths.json e /info. Si tus rutas coinciden, no declares paths.

2 · Embeber el visor en tu host

El visor es HTML, módulos ES y hojas de estilo. No hay bundle que registrar ni framework que inicializar: se cargan los módulos y se pone el tag. 

<!-- Tokens del kit is-* -->
<link rel="stylesheet" href="…/is-webcomponents@eab3227d6a0666bcb2c1f053901c14effb02ca13/dist/cdn/is-base.min.css">
<link rel="stylesheet" href="…/is-webcomponents@eab3227d6a0666bcb2c1f053901c14effb02ca13/dist/cdn/palettes.min.css">
<script type="module" src="…/is-webcomponents@eab3227d6a0666bcb2c1f053901c14effb02ca13/dist/cdn/all.min.js"></script>

<!-- Tema antes del primer pintado -->
<script src="…/iswc-docs/dist/cdn/boot.js"></script>
<link rel="stylesheet" href="…/iswc-docs/src/css/app.css">

<!-- Configuración -->
<script type="application/json" id="docs-config">
{ "apiBase": "https://tu-host/api", "brand": { "title": "Mi API" } }
</script>

<docs-app></docs-app>
<iswc-toast placement="bottom-end"></iswc-toast>

<!-- Los dieciséis componentes en un módulo -->
<script type="module" src="…/iswc-docs/dist/cdn/sw.all.js"></script>

sw.all.js trae el JavaScript de todos los componentes, pero no el CSS: cada uno sigue pidiendo su dist/cdn/<tag>.css. Ese directorio tiene que estar publicado o el visor sale sin estilos.

Precedencia de la configuración

  1. ?conn=, ?spec=, ?api= — el enlace manda.
  2. window.__DOCS_CONFIG__ — lo inyecta el host.
  3. <script type="application/json" id="docs-config"> — la página.

Que el enlace gane es deliberado: tu host fija su API por defecto y aun así alguien puede compartir un enlace a otra sin que tengas que tocar nada.

3 · Levantarlo en local

deno install
deno task build     # src/**.ts → dist/cdn/
deno task serve     # http://localhost:4190

Sin argumentos, index.html arranca con una API de muestra que responde de verdad, así que se puede pulsar «Ejecutar» desde el primer momento. Para desarrollar, deno task dev deja el build en watch.

ComandoQué hace
deno task buildTranspila y aplana a dist/cdn/
deno task devEl mismo build, en watch
deno task serveServidor estático en el 4190
deno task checktsc --noEmit, sin emitir nada
deno task testBuild + deno test tests/

Añadir un componente docs-*

Cuatro pasos, y los cuatro los verifica tests/estructura.test.ts. Hacer solo tres deja un bug mudo: un custom element que no se importa no hace upgrade, así que el tag queda en el DOM sin shadow y la vista sale vacía, sin ningún error en consola.

  1. El módulo y su hoja

    src/components/docs/docs-x.ts
src/components/docs/docs-x.css

  2. Cargarlo en index.html

    <script type="module" src="./dist/cdn/components/docs/docs-x.js"></script>

  3. Importarlo en el barril

    // src/components/docs/all.ts
import './docs-x.js';

  4. Documentarlo aquí

    Entrada en docs/manifest.js y su página en docs/previews/docs-x.html.

Después, deno task test.
